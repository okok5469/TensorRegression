# 2026-08-25 工作进展：v4 adaptive 结果诊断与 SIC 自适应选阶二次修复

## 一、任务背景

近期已经完成三轮 full 数值模拟：

```text
v2: outputs_full_v2
v3: outputs_full_v3
v4: outputs_full_v4_adaptive
```

v2 的问题是 Tensor-ABESS 自动 SIC 选阶严重欠选，典型表现为 `q_hat≈1`，支撑恢复几乎失败。

8.14 的 v3 改动通过固定真实稀疏度：

```text

```

让 Tensor-ABESS 走 fixed-size BCD，验证了在已知 `(4,3,5)` 时算法主体具备较好的支撑恢复能力。因此 v3 可作为 fixed sparsity 主结果，但不能证明自动 SIC 选阶成功。

8.19 的 v4 adaptive 改动引入 MSIC 和全局候选 refine，成功避免了 v2 的 `q≈1` 塌缩，但新的 full 结果显示出现相反问题：自动选阶明显过选。

## 二、今天发现的问题

检查 `numerical_simulation/outputs_full_v4_adaptive` 后，确认该目录结果完整：

```text
raw_results.csv: 560 行

```

但 v4 adaptive 不能作为最终结果，主要原因是 Tensor-ABESS 选阶过大：

```text
Tensor-ABESS q_hat 均值约 112.2
q_hat 中位数约 112.5
140 次 Tensor-ABESS 运行中只有 2 次 exact recovery
绝大多数 q_hat > 60，很多接近 100/125/200

和 v3 fixed-size 相比：

```

结论：v4 已修复 v2 的欠选塌缩，但又进入过选状态；不能直接作为最终模拟实验结果。

## 三、过选原因分析

过选主要来自两处叠加：

1. 8.19 新增 MSIC 的默认 `alpha=1, gamma=1` 对大模型惩罚偏轻；
2. `tensor_bcd_adaptive` 收敛后 `_refine_msic_global_candidates()` 会枚举中高稀疏度候选，并用同一个偏轻 MSIC 直接选分数最低者。

因此 global refine 会倾向选择 RSS 更低但参数更多的候选，典型结果是从真值 `q*=60` 推到 `q_hat=100/125` 甚至更大。

这个问题和 v2 相反：

```text
v2: SIC 惩罚过重，选到 q≈1
v4: MSIC 惩罚过轻，global refine 选到 q≫60
```

## 四、今天完成的代码修改

### 1. 修改 global refine 的 MSIC 打分

文件：

```text
src/tensor_abess/tensor/bcd.py
```

新增参数：

```text
msic_refine_alpha: float = 1.5
msic_refine_gamma: float = 1.0
msic_refine_one_se_scale: float = 1.0
```

核心策略：

1. mode-wise adaptive 仍使用较轻的 MSIC，避免重新回到 v2 的欠选塌缩；
2. 只在 global refine 阶段使用更保守的 `msic_refine_alpha=1.5`；
3. 对候选模型先按 refine MSIC 打分；
4. 找到最低 MSIC 分数后，构造 one-standard-error 风格容忍带；
5. 在容忍带内选择 `q=s1*s2*s3` 最小的候选。

one-SE 容忍带形式：

```text
tolerance = one_se_scale * sqrt(q_best * log(n))
```

这样做的目的不是盲目惩罚大模型，而是在多个候选准则分数非常接近时，优先选择更简单、更稳定的支撑形状。

### 2. 参数透传到 Tensor-ABESS 入口

文件：

```text
src/tensor_abess/tensor/abess.py
```

`tensor_abess(...)` 新增并透传：

```text

msic_refine_gamma
msic_refine_one_se_scale
```

fixed-size 路径不受影响；只有 `target_sparsity=None` 且 adaptive MSIC 路径会使用这些参数。

## 五、小诊断结果

今天没有直接建议再跑 full，而是先用 full baseline 的 3 个固定 seed 做小诊断。

当 `msic_refine_alpha=2.5` 时，惩罚过重：

```text
seed 2026: q=1
seed 2027: q=60
seed 2028: q=2
```

说明 `alpha=2.5` 会让模型重新接近 v2 的欠选塌缩，不能作为默认值。

小网格比较：

```text
alpha_refine=1.5:
seed 2026: sizes=(4,3,5), q=60, Mode-F1=1.000, Exact=1
seed 2027: sizes=(4,3,5), q=60, Mode-F1=1.000, Exact=1
seed 2028: sizes=(4,3,4), q=48, Mode-F1=0.963, Exact=0

alpha_refine=2.0:
seed 2026: sizes=(3,2,5), q=30, Mode-F1=0.886, Exact=0
seed 2027: sizes=(4,3,5), q=60, Mode-F1=1.000, Exact=1
seed 2028: sizes=(1,1,2), q=2, Mode-F1=0.490, Exact=0
```

因此最终默认选择：

```text
msic_refine_alpha=1.5
msic_refine_gamma=1.0
msic_refine_one_se_scale=1.0
```

额外检查：关闭 one-SE 后，seed 2028 会变成：

```text
sizes=(5,4,5), q=100, Mode-F1=0.915, Exact=0
```

这说明 one-SE 小模型优先确实在抑制过选，不是造成欠选的主要原因。

v5 跑完后重点看：

1. `q_hat` 是否从 v4 的均值约 112 拉回到接近 60；
2. Exact recovery 是否明显高于 v4 的 `2/140`；
3. PMSE/R2 是否不再系统性弱于 Tensor-GLasso 和 Vector Lasso；
4. SNR 趋势是否变得更合理，高 SNR 应更容易恢复支撑；

如果 v5 仍过选，可以轻微上调 `msic_refine_alpha` 到 1.7 左右；如果 v5 又欠选，则应降低 `msic_refine_alpha` 或减小 one-SE 容忍带。
