# 2026-08-19 工作进展：SIC 自适应选阶修复与 v4 adaptive 运行准备

## 一、任务背景

昨天的 `outputs_full_v3` 已经补全，但该版本 Tensor-ABESS 使用的是已知真实稀疏度：

```text
target_sparsity=config.sparsity
```

因此 v3 验证的是 fixed-size Tensor-ABESS 的支撑搜索能力，不是 Math 文档中完整算法设想的自动 SIC 选阶能力。

继续检查后发现：如果走 `target_sparsity=None` 的自动选阶路径，旧 SIC 在 full 基准设置下会系统性偏向极小模型，例如 `(1,1,1)` 或 `(1,1,2)`。

full 基准设置为：

```text
n=200
dims=(32,20,25)
true sparsity=(4,3,5)
q*=4*3*5=60
SNR=2
rho=(0.3,0.3,0.3)
```

## 二、旧 SIC 失败原因

旧整体 SIC 公式为：

```text
SIC = n log(RSS/n)
    + q log(n)
    + loglog(n) * sum_m log C(p_m, s_m)
```

逐模态条件 SIC 为：

```text
SIC_m(s) = n log(RSS_s/n)
         + s * block_size * log(n)
         + loglog(n) * log C(J, s)
```

其中 `block_size` 是另外两个模态当前支撑大小的乘积。

在 full seed `2026` 的诊断中：

```text
旧 SIC:
q=1 支撑:       SIC 约 234.7
真实 q=60 支撑: SIC 约 313.6
```

虽然真实支撑显著降低 RSS，但 `q log(n)` 对 `q=60` 的惩罚约为 `317.9`，过大，抵消了拟合改进。

第二个问题是逐模态 BCD 的自我强化：

1. 某一模态先被 SIC 选成很小；
2. 后续模态的 `block_size` 变小；
3. 条件 SIC 更容易继续选择小支撑；
4. 最终陷入 `(1,1,1)` 附近。

所以失败不是张量内积、展开顺序或 Group Splicing 主体错误，而是有限样本下 SIC 惩罚和逐模态局部选阶共同导致的小模型吸附。

## 三、今天完成的修复

### 1. 新增有限样本版 MSIC

新增函数：

```text
src/tensor_abess/tensor/sic.py
- compute_mode_msic_from_rss
- compute_tensor_msic_from_rss
```

新整体准则为：

```text
MSIC = n log(RSS/n)
     + alpha * q * loglog(n)
     + gamma * loglog(n) * sum_m log C(p_m, s_m)
```

默认：

```text
alpha=1
gamma=1
```

新逐模态条件准则为：

```text
MSIC_m(s) = n log(RSS_s/n)
          + alpha * s * block_size * loglog(n)
          + gamma * loglog(n) * log C(J, s)
```

核心变化是把旧的 `q log(n)` 自由度惩罚改成 `q loglog(n)`，降低 full 有限样本场景下对真实矩形块的过度惩罚。

### 2. group adaptive 支持 SIC/MSIC 切换

修改文件：

```text
src/tensor_abess/group/adaptive.py
```

`group_bess_adaptive(...)` 新增参数：

```text
information_criterion: Literal["sic", "msic"] = "sic"
```

默认仍保留旧 `sic`，避免破坏旧调用；张量自适应路径可以显式传入 `msic`。

### 3. tensor adaptive 默认使用 MSIC

修改文件：

```text
src/tensor_abess/tensor/abess.py
src/tensor_abess/tensor/bcd.py
```

`tensor_abess(...)` 新增参数：

```text
adaptive_criterion: Literal["sic", "msic"] = "msic"
```

当 `target_sparsity=None` 时，进入自动 MSIC 自适应选阶。

### 4. 增加全局候选 refine，缓解逐模态局部陷入

单纯把 `log(n)` 改成 `loglog(n)` 后，full seed `2026` 会从欠选跳到过选 `(5,5,5)`，PMSE 反而变差。

因此在 `tensor_bcd_adaptive` 收敛后增加一轮小规模全局候选比较：

1. 在 `s_max` 附近和中间锚点生成候选三元组；
2. 对每个候选 `(s1,s2,s3)` 用边际 top-s warm start；
3. 跑 fixed-size `tensor_bcd`;
4. 用整体 `compute_tensor_msic_from_rss` 选择全局分数最低者。

这一步的目标是避免逐模态序贯更新的局部吸附。

### 5. 修正 s_max 生成

修改文件：

```text
src/tensor_abess/utils/init.py
```

发现旧 `s_max` 在 full seed `2028` 下会给出类似 `(3,3,3)` 的上界，真实 `(4,3,5)` 根本不在搜索空间内。

今天修正为：

1. 保留边际下限 `floor(sqrt(n)/2)`;
2. 去掉过早的 shared cap；
3. 最后统一用 `s1_max*s2_max*s3_max <= 0.7n` 做参数预算裁剪。

修复后 full seed `2028` 的 `s_max` 能覆盖真实稀疏度。

### 6. 新增模拟入口开关

修改文件：

```text
numerical_simulation/data_generation.py
numerical_simulation/methods.py
numerical_simulation/main.py
```

`TensorSimulationConfig` 新增字段：

```text
tensor_abess_mode: Literal["fixed", "adaptive"] = "fixed"
```

CLI 新增参数：

```text
--tensor-abess-mode fixed|adaptive
```

默认仍是 `fixed`，与 `outputs_full_v3` 行为一致。

如果要跑自动 MSIC 版本，必须在命令里加：

```text
--tensor-abess-mode adaptive
```

否则即使输出目录叫 `outputs_full_v4_adaptive`，实际也仍会跑 fixed-size 版本。

## 四、诊断结果

用 full baseline seeds `2026, 2027, 2028` 比较旧 SIC 与新 MSIC adaptive：

```text
seed 2026:
旧 SIC:  shat=(1,1,1), q=1,   Mode-F1=0.411, PMSE=2.751, R2=0.052
新 MSIC: shat=(4,3,5), q=60,  Mode-F1=1.000, PMSE=1.281, R2=0.559

seed 2027:
旧 SIC:  shat=(1,1,1), q=1,   Mode-F1=0.167, PMSE=3.147, R2=-0.059
新 MSIC: shat=(5,5,5), q=125, Mode-F1=0.880, PMSE=1.999, R2=0.328

seed 2028:
旧 SIC:  shat=(1,1,2), q=2,   Mode-F1=0.490, PMSE=2.719, R2=0.063
新 MSIC: shat=(5,4,5), q=100, Mode-F1=0.915, PMSE=2.095, R2=0.278
```

结论：

1. 新 MSIC adaptive 明显修复了旧 SIC 的 `q≈1` 塌缩；
2. 支撑恢复和预测误差都有明显改善；
3. 但 seed `2027/2028` 仍有过选倾向，尚不能认为完全达到 fixed-size v3 的稳定性；
4. 因此 `outputs_full_v4_adaptive` 应作为自动选阶诊断版，与 v3 fixed-size 结果分开解释。

## 六、后续运行建议

下一步建议跑：

```text

```

运行时必须加：

```text
--tensor-abess-mode adaptive
```

跑完后重点比较：

1. Tensor-ABESS 是否仍存在 `q_hat` 过大；
2. baseline、SNR=2、SNR=4 是否比 v3 fixed-size 更接近或至少不差太多；
3. `n=100` 和高维 `64x30x40` 是否因自动过选导致 PMSE 恶化；
4. 相关性实验中 `rho=0.6` 的反常趋势是否仍存在。

如果 v4 adaptive 仍明显过选，可以继续校准 `alpha/gamma`，或增加 one-standard-error / validation refit 规则。
