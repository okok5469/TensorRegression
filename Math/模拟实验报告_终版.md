# 模拟实验报告终版

本报告总结 Tensor-ABESS 数值模拟从早期试运行到最终 v5 adaptive 版本的主要结果、修改原因和最终结论。正式采用的最终结果目录为：

```text
numerical_simulation/outputs_full_v5_adaptive
```

---

## 一、实验目标

数值模拟主要检验三件事：

1. **支撑恢复**：是否能恢复真实的模态支撑 $S_1^*,S_2^*,S_3^*$；
2. **估计与预测**：是否能得到较低的系数误差和测试集 PMSE；
3. **计算效率**：在 $p\gg n$ 的张量回归问题中，是否比非结构化方法更可控。

终版基准设置为：

```text
n_train=200
n_test=500
dims=(32,20,25)
true sparsity=(4,3,5)
q*=60
rho=(0.3,0.3,0.3)
SNR=2
support_shape="continuous"
n_reps=10
```

比较方法包括：

```text
Tensor-ABESS
Tensor-GLasso
Vector Lasso
Oracle OLS
```

---

## 二、版本演进与修改原因

### 1. v1：早期 quick 试运行与实现修复

早期 quick 结果中，Tensor-ABESS 出现明显异常：`q_hat` 膨胀、训练误差过低、测试误差很高，说明问题不是统计设定本身，而是实现层面存在 bug。

关键修复：

1. 修复 `group_splicing` 中交换步 `k_max` 没有同时受 active/inactive 组数约束的问题；
2. 修复 `group_bess_fix` 中 fixed-s 支撑大小可能被破坏的问题；
3. 增加运行时检查，保证 fixed-size 子问题返回的 active group 数等于目标 `s`。

修复后 quick baseline 中 Tensor-ABESS 不再出现支撑爆炸，PMSE、Exact Recovery 和运行时间均明显改善。v1 的主要作用是完成实现校验，不作为 full 正式结果。

### 2. v2：full 自动 SIC 版本，发现严重欠选

`outputs_full_v2` 是第一版完整 full 结果，结果文件本身完整，但 Tensor-ABESS 表现不符合预期。

主要现象：

```text
Tensor-ABESS q_mean=1.193
q_median=1
Exact Recovery=0
Mode-F1=0.061
Element-F1=0.004
PMSE=3.115
R2=-0.046
```

真实模型大小为 `q*=60`，但 v2 的自动 SIC 大量选择 `q≈1`。原因是旧 SIC 中 `q log(n)` 惩罚过重，在 `n=200, q*=60` 的有限样本场景下，真实支撑带来的 RSS 改善被复杂度惩罚抵消，导致逐模态 BCD 进入小模型吸附。

结论：v2 不能作为正式结果，问题集中在自动选阶准则，而不是 Tensor-ABESS 的支撑搜索主体。

### 3. v3：fixed sparsity 版本，验证核心搜索能力

v3 引入固定真实稀疏度路径：

```text
target_sparsity=config.sparsity
```

即 Tensor-ABESS 在每次模拟中使用已知 `(4,3,5)`，只检验固定模型大小下的支撑搜索与估计能力。

总体结果：

```text
q_mean=60.000
q_median=60
Exact Recovery=0.429
Mode-F1=0.627
Element-F1=0.500
PMSE=3.108
R2=-0.101
```

v3 的意义是证明：在模型大小给定时，BCD + Group Splicing 能有效搜索矩形支撑。因此，之前 v2 的失败主要来自自动 SIC 选阶，而不是算法主体完全无效。

但 v3 不是完整自动选阶算法，只能作为 fixed sparsity 参照结果。

### 4. v4：adaptive MSIC 版本，修复欠选但出现过选

v4 引入有限样本版 MSIC，将自由度惩罚从 `q log(n)` 调整为更温和的 `q loglog(n)`，并加入 global candidate refine。

这一步成功避免了 v2 的 `q≈1` 塌缩，但又出现过选：

```text
q_mean=112.157
q_median=112.5
Exact Recovery=0.014
Mode-F1=0.670
Element-F1=0.439
PMSE=3.705
R2=-0.331
```

原因是 v4 的 MSIC 默认 `alpha=1, gamma=1` 对大模型惩罚偏轻；global refine 又会比较较大的候选模型，最终偏向 RSS 更低但参数更多的支撑，导致 `q_hat` 经常达到 100、125 或更高。

结论：v4 是重要诊断版本，但不能作为最终结果。

### 5. v5：最终 adaptive MSIC 版本

v5 保留 v4 中防止欠选的 MSIC 思路，但对 global refine 单独加入更保守的惩罚和 one-SE 小模型优先规则。

最终参数：

```text
msic_refine_alpha=1.5
msic_refine_gamma=1.0
msic_refine_one_se_scale=1.0
```

选择逻辑：

1. mode-wise adaptive 阶段仍使用较轻 MSIC，避免重新塌缩到 `q≈1`；
2. global refine 阶段使用更保守的 MSIC 重新评分；
3. 如果多个候选分数接近，则在 one-SE 容忍带内选择更小的 `q`。

v5 总体结果：

```text
q_mean=47.600
q_median=48
Exact Recovery=0.207
Mode-F1=0.717
Element-F1=0.570
PMSE=2.349
R2=0.166
```

v5 既避免了 v2 的严重欠选，也明显缓解了 v4 的过选，最终作为正式 adaptive 版本使用。

## 六、强点分析

### 1. 支撑恢复明显优于基线方法

在 baseline 下，Tensor-ABESS 的 Mode-F1 为 `0.909`，Element-F1 为 `0.810`，明显高于 Tensor-GLasso 和 Vector Lasso。两类基线方法往往选出大量变量，导致元素级假阳性很高；Tensor-ABESS 借助矩形支撑结构和 Group Splicing，能更集中地恢复真实模态支撑。

### 2. 自动选阶已经回到可控范围

v2 的自动 SIC 几乎塌缩到 `q=1`，v4 又过选到 `q_mean=112.157`。v5 的 `q_mean=47.600, q_median=48`，已经处在真实 `q^*=60` 附近的可解释范围内。

这说明最终 MSIC refine 方案基本达到了预期：既不过度偏小，也不过度偏大。

### 3. 预测表现显著改善

v5 中 Tensor-ABESS 的总体 PMSE 为 `2.349`，优于 Tensor-GLasso 的 `2.949` 和 Vector Lasso 的 `2.863`。baseline 下 Tensor-ABESS 的 PMSE 为 `1.897`，明显接近 Oracle OLS 的 `1.452`。

### 4. SNR 趋势合理

SNR 从 `0.5` 增加到 `4` 时，Tensor-ABESS 的 Mode-F1 从 `0.180` 提高到 `0.953`，Exact Recovery 从 `0` 提高到 `0.6`。这符合高维变量选择的一般规律：信号越强，真实支撑越容易恢复。

### 5. 大样本下接近 Oracle

当 `n=400` 时，Tensor-ABESS 的 Mode-F1 为 `0.952`，PMSE 为 `1.251`，非常接近 Oracle OLS 的 PMSE `1.150`。这说明样本量足够时，最终算法可以有效利用矩形支撑结构。

### 6. 计算效率仍然可接受

v5 的 Tensor-ABESS 运行时间中位数约为 `20.084s`，远低于 Tensor-GLasso 的 `935.922s`。虽然 adaptive refine 比 v3 fixed-size 更慢，但相对于重正则化基线仍有明显效率优势。

## 七、弱点解释

### 1. 低 SNR 场景下仍会欠选

当 `SNR=0.5` 时，Tensor-ABESS 的 `q_median=2`，Mode-F1 只有 `0.180`。这说明在噪声较大时，MSIC 更倾向选择小模型。

这个现象是可以解释的：低 SNR 下真实信号带来的 RSS 改善不稳定，而复杂度惩罚仍然存在，因此自动选阶会偏保守。该弱点不应解释为算法实现错误，而应解释为有限样本、弱信号下变量选择的自然困难。

### 2. 小样本场景仍不稳定

当 `n=100` 时，Tensor-ABESS 的 Mode-F1 为 `0.276`，PMSE 为 `5.803`。虽然 `q_hat` 不再过度膨胀，但支撑恢复很弱。

原因是当前真实模型有 `q^*=60` 个非零元素，而训练样本只有 100 个。在这种接近饱和的设置下，即使利用矩形结构，自动选阶和 OLS refit 都会变得不稳定。

### 3. 高维场景预测仍有压力

在 `64x30x40` 场景中，总变量数达到 76800，Tensor-ABESS 的 `q_median=60`，说明模型大小选择并未失控；但 Mode-F1 降至 `0.651`，PMSE 升至 `3.419`。

这说明高维困难主要不是过选，而是边际初始化和支撑定位难度增加。真实矩形块在更大的张量空间中更难被稳定定位。

### 4. Exact Recovery 不应作为唯一标准

v5 的总体 Exact Recovery 为 `0.207`，低于 v3 fixed 的 `0.429`。这是因为 v5 是自动选阶版本，不再使用真实稀疏度。

但 v5 的 Mode-F1、Element-F1、PMSE 和 R2 均优于 v3 fixed，说明即使没有每次完全精确恢复三个模态集合，整体预测和估计仍更好。正式汇报中应以 Mode-F1、Element-F1、PMSE 和 R2 为主，Exact Recovery 作为严格补充指标。

---

## 八、最终结论

终版 v5 adaptive 结果可以作为正式模拟实验结果使用。

核心结论如下：

1. Tensor-ABESS 在矩形支撑张量回归中显著优于 Tensor-GLasso 和 Vector Lasso；
2. 最终 MSIC 自适应准则有效解决了 v2 欠选和 v4 过选问题；
3. 在 baseline、强信号、较大样本和低/中维设置下，Tensor-ABESS 能获得接近 Oracle 的支撑恢复和预测效果；
4. 在低 SNR、小样本和极高维设置下，方法仍会出现欠选或定位不稳定，这是当前方法的主要局限；
5. v3 fixed-size 可作为已知稀疏度参照，v5 adaptive 应作为最终主结果。

最终报告建议表述为：

> 数值模拟表明，当真实系数张量具有矩形稀疏结构时，Tensor-ABESS 能够有效利用模态结构进行变量选择。与 Tensor-GLasso 和 Vector Lasso 相比，该方法在支撑恢复、假阳性控制、预测误差和计算效率方面整体表现更好。最终自适应 MSIC 版本在多数场景下能够自动选择合理模型大小，但在弱信号、小样本和极高维设置中仍存在保守欠选或定位不稳定的问题。
