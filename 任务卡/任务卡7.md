# 任务卡7：Tensor-ABESS 实证过拟合归因与模型选择机制诊断

## 一、任务背景

目前 Tensor-ABESS 已有三个算法版本：

| 版本 | 核心特点 |
|---|---|
| v5-original | 原始 BCD + 原候选规模网格 + 原 MSIC |
| v5.1-bcd-fix | 修复 fixed BCD，保留原网格与 MSIC |
| v5.2-search-final | 修复 BCD + 完整候选规模网格，保留原 MSIC |

其中 v5.2 已正式发布，完整700任务模拟已经完成。

模拟发现：

- 完全恢复次数由138/700提高到182/700。
- 总体平均PMSE由2.2368恶化至2.3813。
- n=400场景恢复显著改善。
- n=100及部分弱信号场景预测恶化。

LEMON EEG实证结果更加突出：

| 模型 | RMSE | R² |
|---|---:|---:|
| Covariates Only | 0.3175 | 0.3679 |
| Tensor-ABESS v5 | 0.3717 | 0.1214 |
| Tensor-ABESS v5.2 | 0.5046 | -0.5970 |

v5.2出现q=80的外层折由原来的1/15增加到5/15，训练误差下降、测试误差上升。

目前尚不能判断这些变化主要来自：

1. BCD正确性修复后，大模型训练拟合更加充分。
2. A2候选规模补全改变了全局模型选择。
3. 原MSIC在更充分的搜索下不能有效限制过拟合。
4. LEMON EEG特征本身缺乏稳定的增量预测信息。

**本次任务目标是区分这些因素，建立可靠的下一步研究依据。**

特别强调：

- 不直接回退v5。
- 不修改已发布的v5.2算法。
- 不调整正式MSIC或caps。
- 不覆盖旧模拟和旧实证结果。
- 不根据已经查看的外层测试结果挑选新参数。
- 不干扰正在使用v5.2的HCP/NKI队友。

# Phase A：LEMON三版本严格归因

## A1. 研究目标

需要区分：

\[
v5\xrightarrow{\text{BCD修复}}v5.1
\xrightarrow{\text{候选网格补全}}v5.2
\]

分别观察两次修改对LEMON预测性能的影响。

最重要的问题：

**LEMON中v5.1与v5.2是否实际得到相同的支撑和预测？**

此前结构审计指出，LEMON外层训练样本量约116，旧caps下的候选规模网格可能已经完整。

如果v5.1与v5.2实际候选集合相同，那么A2不应被直接认定为LEMON恶化的原因。

但仍需核对候选顺序、初始化、缓存、并列选择和最终结果，不能仅凭理论集合相同就宣布输出完全一致。

## A2. 固定已有LEMON实验

使用既有数据：

```text

X.shape = (145,61,16,5)
y = log(TMT_5)
协变量：原年龄分组和性别，共8列
外层：3次重复 × 5折
```

保留原：

- subject ID与顺序；
- EEG特征；
- 协变量编码；
- 训练/测试划分；
- 折内残差化与标准化；
- 初始化和求解参数；
- 原MSIC及one-SE风格规则；
- 随机种子；
- 评价指标。

优先读取此前完成的v5与v5.2完整OOF结果。

**本阶段只需补跑v5.1的15个外层Tensor-ABESS拟合。**

除非身份检查失败，否则不重复训练其他对照算法。

## A3. 源码和环境审计

检查三个历史版本的完整源码快照及SHA256。

确认：

- v5来自原始冻结版本；
- v5.1来自正式BCD修复版本；
- v5.2来自正式发布版本；
- 导入的代码确实属于目标版本；
- v5.1没有意外采用A2网格；
- 三版本调用配置完全一致。

采用隔离进程加载历史版本。

不得通过覆盖生产`src/tensor_abess`来切换版本。

如果同样的配置无法得到一致输入、划分和环境身份，必须先解决差异，再继续结果比较。

## A4. 逐折对照

|---|---|---|---|
| q | | | |

重点分析原来出现q=80的折，以及新版新增q=80的折。

绘制三版本逐折测试误差、q/Q和训练—测试误差差距的配对图。

## A5. 两个关键验证

### 验证一：v5.1与v5.2是否等价？

如果二者：

- 候选规模集合一致；
- 候选对应的模型和得分一致；
- 最终B、支撑及预测一致；

则可以确认LEMON中的变化主要发生在v5→v5.1。

如果两者不一致，必须定位具体差异，检查候选顺序、初始化、浮点并列、缓存及版本身份。

不能仅因为两者候选规模集合相同，就忽略运行路径的差异。

### 验证二：BCD修复对泛化的影响

比较v5与v5.1：

- 训练RSS是否普遍下降；
- q是否更容易变大；
- MSIC是否更偏好大模型；
- 测试RMSE是否同步恶化；
- 是否存在更优训练拟合但更差测试预测的典型外折。

区分BCD搜索正确性与统计泛化能力。

不能因为旧版测试RMSE更小，就判定已知BCD搜索缺陷应当恢复。

# Phase C：诊断BCD修复与MSIC的关系

## C1. 核心问题

现在怀疑存在一个统计现象：

**BCD修复使固定规模搜索得到更低的训练RSS，但MSIC对新增训练拟合收益的复杂度惩罚不足，因此更容易选择大模型。**

这是需要验证的假设，不是已经证明的结论。

本阶段仅做机制研究，不修改正式算法。

## C2. 重现全局候选选择过程

在Phase A识别出的代表外折中，记录：

1. Group Lasso初始化规模；
2. Adaptive BCD终态；
3. Global MSIC候选集合；
4. 每个候选的q、RSS及MSIC；
5. one-SE风格容忍带；
6. 最终选择q；
7. 候选搜索路径与最终OLS状态。

重点比较v5和v5.1同一规模候选的训练RSS及MSIC变化。

例如：

如果原q80模型RSS较高，而修复后RSS明显下降，导致MSIC排序改变，需要定量分解：

\[
\Delta MSIC
=
n\log\frac{RSS_{\mathrm{new}}}{RSS_{\mathrm{old}}}
+\Delta\mathrm{Penalty}.
\]

在相同规模与同一惩罚公式下，惩罚变化应为零；若支撑规模或形状不同，则单独记录惩罚变化。

## C3. 训练内部模型复杂度诊断

选择预先确定的代表外层训练集。

只使用这些外层训练受试者，重新进行内部验证。

比较：

- Covariates Only；
- 原MSIC自适应ABESS；
- 固定小规模ABESS；
- 固定中规模ABESS；
- 固定大规模ABESS。

所有候选支撑必须在相应内训练折重新搜索，所有预处理也必须重新拟合。

不能在116名完整外训练样本上提前选好支撑，再拿该支撑进行内部交叉验证。

重点观察：

- q增大时训练误差是否持续下降；
- 内部验证误差是否反而增加；
- MSIC最优q与内部验证较优q是否出现系统性偏离。

这些实验旨在诊断有限样本复杂度，不用于修改已经完成的外层预测。

## C4. MSIC研究边界

可以利用固定候选库进行探索性重评分，检查不同惩罚项对q选择的影响。

但必须明确：

- 这是事后机制诊断；
- 不能根据已有LEMON外层测试结果确定新alpha；
- 不能直接采用让旧15折测试RMSE最低的参数；
- 不在本任务中发布v6；
- 不覆盖v5.2正式结果。

如发现确有必要改进模型选择，单独设计下一轮研究：

**保留修复后的BCD，在新的预声明模拟和独立确认数据上研究MSIC、复杂度限制或训练内选择准则。**

可以同时把“不加入EEG特征”的q=0模型作为未来实证预测框架的候选研究方向，但不得在本任务直接混入正式Tensor-ABESS算法。
