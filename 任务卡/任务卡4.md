# 任务卡4：Tensor-ABESS A2方案最终验证与算法版本确定

## 一、任务目标

本次任务的核心是**判断是否应该正式采用 A2 候选搜索方案，并最终冻结用于数值模拟和实证分析的 Tensor-ABESS 算法版本**。

本任务不以让某个算法在特定数据集上获得更好成绩为目标，而是验证算法改进是否具有稳定性、合理性和可推广性。

研究顺序：

1. 审核 A2 已有实验结果与实现。
2. 使用新增独立模拟场景检验 A2 的稳健性。
3. 决定是否正式采用 A2。
4. 在选定的搜索机制上决定是否保留原 MSIC。
5. 冻结算法版本并准备队友同步及后续全量实验。

**本任务暂不执行 700 个正式模拟任务，也不重新运行 LEMON、HCP-YA、NKI-Rockland 实证。**

---

## 二、当前研究背景

目前生产算法为：

`v5.1-bcd-fix`

该版本已经修复 fixed BCD 搜索缺陷，MSIC 使用原参数。

任务卡3比较了：

| 方案 | caps | 候选规模网格 |
|---|---|---|
| A0 | 原版 | 原版 |
| A1 | 放宽 | 原版 |
| A2 | 原版 | 完整合法整数 |
| A3 | 放宽 | 完整合法整数 |
| A4 | 放宽 | 粗到细搜索 |

已有开发与独立确认实验发现：

- A2 的支撑恢复表现明显优于 A0。
- A2 的整体预测 PMSE 略低于 A0，但改善幅度较小。
- A2 计算成本有所增加，但远低于 A3。
- A3 虽扩大真实支撑规模的覆盖率，却造成明显预测恶化和计算成本增加。
- 多初始化尚未显示稳定收益。
- A2 在 n=100 时仍受旧 caps 限制。
- A3 上的 MSIC 参数研究不能直接等同于 A2 的最优参数研究。

因此，本任务优先研究 A2，不再将 A1、A3、A4 作为同等优先级的正式候选。

## 三、Phase A：A2代码与历史结果复核

### A1. 确认版本关系

检查以下现有研究版本：

```text
v5-original
v5.1-bcd-fix
v5.2-candidate-search
```

确保：

- 开发基础为 v5.1。
- fixed BCD 修复完整保留。
- A2 仅采用旧 caps 与完整合法整数候选规模网格。
- 原 Group-BESS、OLS、DGP、MSIC 公式不改变。
- 模型的总参数容量约束不改变。
- 不使用真实支撑或测试数据生成候选。

目前 v5.2 是研究版本，不得直接替换生产代码。

### A2. 检查A2实现

重点检查：

- 是否枚举旧 caps 范围内满足容量约束的全部整数三元组。
- 是否有重复、遗漏或越界。
- 是否影响 adaptive BCD 的原有行为。
- 是否保持候选支撑位置搜索的定义不变。
- 是否保持 MSIC 默认参数不变。
- 是否存在额外的缓存、初始化或求解差异。

特别注意：A2 的“完整”仅指**旧 caps 内的合法规模枚举完整**，不代表穷举所有支撑位置。

### A3. 复核已有独立确认

直接检查任务卡3保存的 90 组独立确认结果，验证：

- A0 Exact = 6/90。
- A2 Exact = 26/90。
- A0 PMSE ≈ 3.1184。
- A2 PMSE ≈ 3.0827。
- n=400、SNR=2/4 时，A2 恢复优势是否可复现。
- A2 相对于 A0 的计算成本。
- 不同 n、SNR 下的差异。

优先复用已经校验的结果文件，不因本任务重新计算而浪费大量资源。

输出：

`doc/A2_EXISTING_EVIDENCE.md`

## 四、Phase B：新增独立场景验证A2

这是本任务最重要的阶段。

已有模拟主要围绕真实支撑形状 `(4,3,5)`，不能仅凭这一形状决定 A2 是否适合成为正式算法。

### B1. 冻结实验方案

在运行新的模拟前，先保存不可覆盖的实验协议，明确：

- 待比较版本；
- 新随机种子；
- 数据生成参数；
- 真支撑形状；
- 评价指标；
- 模型选择及版本批准标准；
- 计算预算。

已有开发集和确认集的结果可以用于制定实验方案，但不能把已经反复查看的测试结果再称为全新独立确认。

新增模拟使用此前未使用的随机种子。

### B2. 核心比较

只比较：

```text
A0：v5.1，旧caps + 旧grid
A2：v5.1，旧caps + 完整整数grid
```

两组保持：

```text
mode MSIC alpha = 1
global MSIC alpha = 1.5
gamma = 1
one_se_scale = 1
```

保持其他求解设置相同。

采用配对设计：相同训练数据、测试数据和随机种子。

### B3. 验证不同真实支撑形状

除原 `(4,3,5)` 外，增加其他预先确定的矩形稀疏结构，例如：

```text
(2,3,4)  q=24
(3,4,5)  q=60
```

研究不同支撑规模及模态分配下，A2 的表现是否仍然合理。

不能使用真实支撑调整 A2 的搜索上界或候选集合。

建议保持原有 DGP，并选取代表性样本量与信噪比：

```text
n = [100, 200, 400]
SNR = [0.5, 2, 4]
```

可增加一个更强相关性的设置，以检查候选网格改善是否依赖原有相关结构。

正式组合和每场景重复次数根据计算预算在运行前确定，确保有足够的独立重复，不以单个随机种子作结论。

如果某个真实规模不满足模型容量约束，明确标为不可表示场景，不以其精确恢复失败评价选阶准则本身。

### B4. 评价指标

至少统计：

```text
Exact Recovery
Mode-F1
Element-F1
PMSE
R²
q_hat
过选率
欠选率
训练/测试误差
计算时间
候选模型数
```

还要分开记录：

1. 真实规模是否被 caps 允许；
2. 真实规模是否进入候选网格；
3. 真实支撑位置是否进入候选池；
4. MSIC 是否最终选中真实支撑。

这能区分候选覆盖、位置搜索和模型选择三个问题。

### B5. 判断A2是否值得采用

综合评价：

**恢复能力：** A2 是否在多个场景中稳定改善或保持支撑恢复？

**预测能力：** A2 是否没有出现不可接受的 PMSE 恶化？

**计算成本：** 完整枚举增加的时间与恢复收益是否相称？

**适用范围：** 改善是否仅发生在 n=400 或个别真实支撑结构？

在查看新增实验结果之前，明确具体的可接受性能退化、成本预算和主要决策指标，并进行敏感性分析，不得事后为选中 A2 修改标准。

如果 A2 仅在有限场景中改善恢复，但预测收益不足以抵消成本，应明确讨论其作为可选研究策略而非默认策略的可能性。

## 五、Phase C：冻结搜索机制后决定MSIC

只有完成 A2 版本决策后，才进入该阶段。

### C1. 如果决定采用A2

首先保留原 MSIC 作为基线：

```text
alpha = 1.5
gamma = 1
one_se_scale = 1
```

然后独立研究是否有必要调整 MSIC。

重点比较少量已有依据的候选，例如：

```text
原准则：alpha=1.5，scale=1
温和候选：alpha=2，scale=0
```

必须注意：

之前 alpha=2 的部分研究发生在 A3 候选池上。

**不能把 A3 上较好的 MSIC 参数直接认定为 A2 上的最佳参数。**

先对固定 A2 候选库开展受控重评分；如果候选规则确有希望，再使用预先冻结的独立实验验证。

如现有研究证据不足，不强制修改 MSIC。

### C2. 如果决定不采用A2

保留 v5.1 作为当前正式版本。

总结拒绝 A2 的原因，例如：

- 收益集中于少数场景；
- 预测表现不稳定；
- 计算成本过高；
- 其他真实支撑形状下恢复优势不能保持。

不允许为了让 A2 被采用，继续反复调整同一批测试数据上的 MSIC。

### C3. MSIC验收重点

不能只看 PMSE，还必须检查：

- 强信号下是否欠选；
- 弱信号下是否过选；
- 是否频繁选择 q=1；
- 是否频繁触及参数容量上限；
- Exact、F1 与预测表现的权衡；
- 新搜索机制是否改变 MSIC 选阶行为。

若 MSIC 新规则没有充分依据，则保留原 MSIC。

## 六、Phase D：正式版本决定与冻结

根据前述实验，给出明确决策。

可能的结果：

| 决策 | 正式算法 |
|---|---|
| D1 | 保留 v5.1：BCD修复，旧搜索，旧MSIC |
| D2 | 采用 A2：BCD修复，完整整数网格，旧MSIC |
| D3 | 采用 A2 + 经验证的新MSIC |

不得为了形成新版本而强制选择 D2 或 D3。

建议最终正式版本使用独立且固定的版本号、Git commit 和源码指纹。

如采用 D2，可命名为 `v5.2-search-final`。

如采用 D3，可命名为 `v6-final`。

在最终批准前，研究版本不得标记为正式发布。

### 必须完成

- 全部新增测试和现有相关回归测试通过。
- 原公共接口兼容性检查通过。
- 算法配置、默认参数和源码固定。
- 版本源码、依赖、随机种子与关键验证结果可复现。
- 新旧版本差异清晰记录。
- 不允许覆盖历史正式结果。
- 确认最终算法不依赖真实模拟支撑或独立测试数据选择候选。

最终形成一套可用于完整数值模拟和三个实证数据集的统一算法代码。

