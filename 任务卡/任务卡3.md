# Codex 任务卡：Tensor-ABESS 候选支撑搜索改进与 MSIC 自适应选阶研究

## 一、研究背景与目标

本项目目前已完成 Tensor-ABESS 的 `v5.1-bcd-fix` 版本。

上一阶段已经修复 fixed BCD 中的损失回升、循环与未返回最优已访问状态的问题。53 项限定测试通过，算法搜索正确性得到改善。

但是，后续 MSIC 消融实验发现一个更基础的问题：

**算法的候选支撑集合存在覆盖不足，导致真实模型即使满足理论容量限制，也可能无法被当前搜索机制考虑。**

根据 `MSIC_ABLATION_REPORT.md`：

- 27 个模拟数据集中，18 个候选池包含某种形状的 \(q=60\) 模型。
- 只有 9 个候选池包含真实规模三元组 \((4,3,5)\)。
- 只有 3 个候选池包含真实的完整支撑位置。
- 当 \(n=100\)，第三模的搜索上界只有 4，真实支撑大小 5 被排除。
- 当 \(n=400\)，候选规模网格跳过了第二模的大小 3。
- 当 \(n=200\)，真实规模可以进入候选池，但支撑位置搜索仍可能失败。

因此，我们不能简单把选阶失败归因于 MSIC 惩罚系数。

本次研究目标：

1. 查明候选支撑覆盖不足的具体机制。
2. 改善逐模搜索上界与候选规模生成规则。
3. 研究支撑位置搜索的稳定性。
4. 在候选搜索机制得到验证后，重新研究 MSIC 选阶。
5. 判断是否有充分依据形成新的正式算法版本。
6. 评估对原有数值模拟和三个实证数据集的影响。

**核心原则：先完善候选搜索，再调整选阶准则。两者必须独立实验、独立记录。**

## 三、Phase A：全面诊断候选搜索机制

这一阶段先不修改 MSIC。

### A1. 梳理当前候选生成流程

追踪：

```text
边际预筛
    ↓
Group Lasso 初始化
    ↓
逐模搜索上界 caps
    ↓
Adaptive BCD
    ↓
全局候选规模网格
    ↓
固定规模 BCD 支撑搜索
    ↓
全局 MSIC 评分
    ↓
最终支撑选择
```

重点回答：

- `caps` 如何从初始化结果和样本量计算？
- 为什么要求三个逐模上界的乘积不超过 `floor(0.7n)`？
- 这种限制是否过度压缩某些模式？
- 为什么候选规模使用少量离散点，而不是全部合法整数？
- 全局候选有没有遗漏已经满足容量约束的合理支撑大小？
- 即使真实规模进入候选池，为什么实际支撑位置仍可能搜索失败？
- 边际预筛是否已排除真正有效的切片？

记录每一阶段的候选规模、候选位置及排除原因。

### A2. 区分三种完全不同的失败

**第一类：上界不可达**

真实规模满足总体参数约束：

\[
s_1^*s_2^*s_3^*\leq \lfloor0.7n\rfloor
\]

但由于逐模 caps 限制，真实三元组无法进入搜索空间。

**第二类：规模网格遗漏**

真实三元组满足 caps，却没有包含在最终枚举的候选组合里。

**第三类：位置搜索失败**

真实三元组进入候选集合，但 BCD 和 Group-BESS 没有找到对应的真实支撑位置。

分别统计这三类失败，不得统一归结为“MSIC 选阶失败”。

此外，应区分真实规模三元组、参数总数 \(q\) 和真实支撑位置。三者不是同一个指标。

真实支撑信息只允许用于模拟诊断和结果评价，不能用于候选生成或正式算法调参。

### A3. 输出诊断

建议输出：

```text
candidate_coverage_audit.csv
caps_diagnostics.csv
size_grid_diagnostics.csv
support_search_diagnostics.csv
```

报告每个模拟数据集：

- 样本量、维度、SNR；
- 逐模 caps；
- 全局容量限制；
- 合法候选规模数量；
- 最终实际搜索数量；
- 真实三元组是否可达；
- 真实三元组是否进入候选集合；
- 真实支撑位置是否出现在候选支持中；
- 若失败，首次在哪个阶段被排除。

## 四、Phase B：改进候选规模搜索机制

这部分是本次最核心的研究工作。

**本阶段保持 MSIC 默认参数不变：**

```text
mode alpha = 1
refine alpha = 1.5
gamma = 1
one_se_scale = 1
```

### B1. 改进逐模 caps

重点研究是否可以不再强制：

\[
s_{1,\max}s_{2,\max}s_{3,\max}
\leq\lfloor0.7n\rfloor.
\]

原规则可能导致某个模式的上界被不必要地缩小。

尝试将两个概念分开：

1. 每个模式允许搜索的最大规模；
2. 每个最终候选模型的总参数限制。

例如保留候选级约束：

\[
s_1s_2s_3\leq\lfloor0.7n\rfloor,
\]

但不一定要求三个最大上界的乘积也满足该条件。

该方案只是待验证候选，不能直接认定优于原规则。

需要检查：

- 是否使合理模型重新进入可搜索空间；
- 是否显著增加计算成本；
- 是否引入更多大模型过拟合；
- 是否影响 Group-BESS 的数值稳定性。

新 caps 必须由训练数据、维度和通用规则决定，不能使用模拟真实支撑大小。

### B2. 改进全局候选规模网格

目前使用的稀疏候选整数网格可能遗漏中间规模。

例如某模式上界为 6，候选集合可能为：

```text
{1, 2, 4, 5, 6}
```

直接遗漏大小 3。

研究以下方案：

**方案 A：完整合法整数枚举**

对于：

\[
1\leq s_m\leq s_{m,\max},
\]

枚举满足参数容量限制的全部合法三元组。

优点是规模覆盖完整；缺点是可能增加计算成本。

**方案 B：粗到细候选搜索**

先通过较稀疏的规模网格搜索，再围绕训练准则较好的候选补充邻近规模。

要求邻域扩展规则预先确定，不得根据测试误差补充候选。

**方案 C：原候选网格**

作为不变对照。

在模拟规模较小时，尽可能将完整合法枚举作为参照，用于判断粗到细搜索有没有遗漏重要候选。

如果完整枚举计算成本过高，需要引入明确的候选数量或时间预算，并记录哪些规模因预算被排除，不能把预算截断后的搜索称作完整枚举。

### B3. 分离两个改进因素

至少建立以下四组：

| 组别 | caps | 规模网格 |
|---|---|---|
| A0 | 原版 | 原版 |
| A1 | 新版 | 原版 |
| A2 | 原版 | 新版 |
| A3 | 新版 | 新版 |

四组都使用修复后的 fixed BCD 和相同的原始 MSIC。

通过这种设计判断：

- 改进 caps 单独带来什么变化；
- 改进网格单独带来什么变化；
- 两者一起改进是否有效；
- 候选增加是否导致过选、耗时或预测误差恶化。

所有对照使用相同生成数据、相同随机种子和相同测试集。

## 五、Phase C：研究支撑位置搜索的稳定性

只有规模搜索机制的覆盖问题得到充分检查后，再研究位置搜索。

当前报告显示，部分场景中即使真实规模已经进入候选池，算法仍然无法准确恢复真实位置。

因此需要检查：

- 边际预筛是否遗漏真实有效切片；
- 初始化是否容易落入局部解；
- 不同初始支撑是否导致明显不同结果；
- fixed BCD 是否能通过多次初始化改善位置搜索；
- 更充分的位置搜索是否明显增加训练过拟合风险。

建议进行一个独立的多初始化实验。

对同一固定规模：

1. 使用原边际得分初始化。
2. 尝试少量预先定义的其他训练内初始化策略。
3. 在相同 fixed BCD 算法下分别搜索。
4. 根据训练目标选择候选最优结果。
5. 使用独立测试数据评价是否改善泛化。

必须记录每次初始化的支撑、训练 RSS、最终位置和计算时间。

不得根据真实支撑或独立测试结果选择初始化。

模拟中可以额外计算真实支撑下的 Oracle OLS，帮助判断是搜索失败还是估计本身困难，但 Oracle 信息不得进入正式算法。

## 六、Phase D：候选搜索机制的模拟验收

暂时不启动完整 700 任务模拟。

先进行小规模配对实验。

采用原基准设置：

```text
dims = (32, 20, 25)
true_sparsity = (4, 3, 5)
rho = (0.3, 0.3, 0.3)
n_test = 500
```

初步场景：

```text
n = [100, 200, 400]
SNR = [0.5, 2, 4]
```

首先使用历史可复现数据完成机制诊断。

随后在新增的、事先固定的模拟种子上增加重复次数，建议每场景至少 10 次；资源允许时进一步增加，以避免只有 3 次重复导致结论被个别样本主导。

评价：

- 真实三元组的可达率和候选覆盖率；
- 真实支撑位置进入候选池的比例；
- Exact Recovery；
- Mode-F1、Element-F1；
- 选中参数数量 \(q\)；
- 过选率与欠选率；
- PMSE、R²；
- 运行时间和候选数量。

特别注意：

**候选覆盖率提高不等于算法整体性能一定提高。**

更大的候选池既可能帮助恢复真实模型，也可能增加训练过拟合机会。

需要同时衡量支撑恢复、预测效果和计算效率。

如果候选搜索机制尚未获得有说服力的改善，停止进入正式 MSIC 调整阶段，并总结原因。

## 七、Phase E：在改进后的候选搜索机制上研究 MSIC

本阶段必须在候选搜索机制固定之后进行。

### E1. 重新评估当前 MSIC

统一使用新的候选机制，首先运行原 MSIC：

```text
refine alpha = 1.5
gamma = 1
one_se_scale = 1
```

检查：

- 是否仍出现 q 接近容量上限的模型；
- 是否仍有大量 q=1；
- 候选搜索改进后，MSIC 的选阶表现发生了什么变化；
- 旧版 MSIC 的问题是否部分源于候选池不足。

### E2. MSIC 参数消融

初步比较：

```text
alpha = [1.5, 2.0, 3.0]
one_se_scale = [0, 0.5, 1.0]
gamma = 1.0
```

同时保留原 tensor-SIC 与 BIC 风格准则作为诊断对照。

优先研究历史实验中表现相对温和的：

```text
alpha = 2
one_se_scale = 0
```

但它只是候选方案，不是已经确定的最优准则。

### E3. MSIC 比较规则

首先在同一个已搜索的候选库上重新评分，隔离 MSIC 改动本身的影响。

然后对有希望的规则进行完整重新拟合，验证结果是否一致。

候选规则不能只按总体平均 PMSE 排名，还应比较：

- 不同 SNR 下的表现；
- 小样本与大样本下的表现；
- 欠选和过选；
- 支撑恢复；
- 预测表现；
- 计算时间。

特别重视强信号条件下是否因惩罚过强而漏选真实变量。

本次新实验应预先固定候选规则，在开发模拟数据上进行选择，再使用独立的确认模拟数据评价；不能反复根据同一批测试结果挑选最优参数。

### E4. 内部交叉验证作为补充对照

可以继续保留 CV 选阶作为参考，但必须考虑：

- 每个内折的候选位置必须重新搜索；
- 内训练样本量较小，搜索可能更加不稳定；
- 固定 q 不代表固定矩形形状；
- 内折与完整训练集的容量限制可能不同；
- 不得用已固定的全训练集支撑进行伪交叉验证。

不预设 CV 一定比 MSIC 更好。

## 十、测试与验收标准

至少新增以下测试。

**候选生成测试**

- 所有生成的三元组均满足维度与参数容量限制。
- 不重复、不越界，顺序可复现。
- 当使用完整合法枚举时，不遗漏任何满足规则的整数三元组。
- 验证历史 n=100、n=400 的结构性遗漏能够被准确诊断。
- 更改 caps 不破坏最终模型的参数上限。
- 计算预算截断必须有明确记录。

**优化正确性测试**

- 新候选调用不破坏 v5.1 的 fixed BCD 正式接受损失单调性。
- 最终返回已访问候选中的最佳完整拟合状态。
- 保持 Group-BESS 固定规模不变量。
- OLS、RSS 与张量系数一致。
- 支撑位置搜索可复现。

**统计与实验测试**

- 不使用真实支撑决定候选。
- 不使用独立测试误差调节候选生成。
- 相同输入和种子下结果可复现。
- MSIC 重评分不改变候选库。
- 不同版本对照严格使用相同模拟数据。
- 每个实验产物记录对应源码版本和配置。

运行现有相关测试，并说明测试覆盖范围，不得把限定测试通过表述为整个仓库全面通过。

## 十二、执行优先级与停止条件

严格按以下顺序执行：

**P0：原搜索机制审计**

找到 caps、规模网格及位置搜索各自的限制。

**P1：候选搜索改进**

分别实现和比较 caps、规模网格的修改。

**P2：支撑位置搜索研究**

检查初始化和固定规模位置搜索对候选覆盖的影响。

**P3：小规模模拟验收**

确认覆盖改善是否能转化为支撑恢复或预测收益，并衡量计算开销。

**P4：MSIC 重新研究**

在固定候选搜索机制后比较不同选阶准则。

**P5：版本决策与团队交付**
