# Codex 任务卡：Tensor-ABESS 算法修复、MSIC 选阶研究与团队版本同步

## 一、任务背景与目标

本项目研究三阶张量稀疏回归算法 Tensor-ABESS。当前已完成 v5 adaptive 数值模拟，并在 LEMON EEG、HCP-YA 和 NKI-Rockland 数据集上开展实证分析。

LEMON 的增量预测实验发现，Tensor-ABESS 在某次外层交叉验证中异常选择了 \(q=80\) 的大模型，出现严重过拟合。

根据 `DIAGNOSTIC_REPORT.md`，逐阶段诊断已确认：

1. BIC/Group Lasso 初始化得到 \(q=3\)，不是异常来源。
2. 自适应 BCD 阶段得到 \(q=5\)，训练 RSS 为 8.4302。
3. Global MSIC Refinement 最终选择 \(q=80\)，训练 RSS 为 1.2341。
4. 最佳小模型与 q80 的 MSIC 差约为 25，超过 one-SE 风格容忍带约 19.5，因此小模型未被选中。
5. OLS 数值求解检查正常，没有发现秩亏或求解器错误。
6. 固定规模 BCD 出现训练 RSS 回升和循环，未返回迭代过程中训练 RSS 最小的状态。
7. 在异常外折的训练集内部交叉验证中，q80 的预测表现极差，明显不受验证数据支持。

因此，本次任务不是单纯为了改善某个数据集的结果，而是修复算法正确性，并研究现有 MSIC 准则在有限样本下的选阶表现。

**总目标：**

- 修复 fixed BCD 的搜索正确性问题；
- 保留可复现的原 v5 版本；
- 独立研究 MSIC 的过选与欠选问题；
- 判断是否需要形成新的自适应选阶版本；
- 准备向另外两名队友同步算法修复；
- 评估并执行必要的数值模拟复验。

## 三、阶段一：修复 fixed BCD 搜索缺陷（P0）

### 3.1 审计相关源码

重点检查：

```text
src/tensor_abess/tensor/bcd.py
src/tensor_abess/tensor/abess.py
src/tensor_abess/tensor/ops.py
src/tensor_abess/tensor/sic.py

src/tensor_abess/group/bess_fix.py
src/tensor_abess/group/splicing.py
```

以上位置是历史文档中的实现位置，具体函数及调用关系以当前仓库为准。

重点追踪固定支撑规模下的 BCD：

\[
S_1\rightarrow S_2\rightarrow S_3
\rightarrow \widehat B\rightarrow RSS.
\]

检查每次更新时：

- 是否重新初始化支撑，导致丢失上一轮更好的状态；
- 是否允许接受完整训练损失更高的候选；
- 是否在局部组更新和完整张量 OLS 之间使用了不一致的损失；
- 是否存在支撑状态循环；
- 是否只返回最后一次 BCD 迭代，而不是历史最优解；
- 是否在支撑更新后正确重新计算 OLS、RSS、MSIC；
- 是否保留固定支撑规模和参数上限等不变量。

### 3.2 必须实现的修复

在不改变原有目标函数和 Group-BESS 数学定义的前提下：

**A. 保存历史最优状态**

固定规模 BCD 至少维护：

```python
best_supports
best_B
best_RSS
best_loss
best_iteration
```

保存最优状态时，保证支撑、系数、损失及相关元数据属于同一次完整拟合，不得拼接不同迭代的结果。

**B. 建立合理的候选接受规则**

每次候选更新后，对完整矩形支撑执行 OLS，并在统一目标函数下比较。

对固定支撑规模、相同训练数据和相同损失定义，接受更新不应使训练损失上升超过数值容差。

如算法设计确实需要非单调搜索，应明确区分探索状态与正式接受状态，且必须返回已访问候选中的最优状态。

**C. 处理状态循环与收敛**

增加循环识别和一致的停止条件，避免在多个已访问支撑之间重复切换，直到达到最大迭代次数才结束。

**D. 保持结构正确**

确保：

\[
|S_m|=s_m,\qquad m=1,2,3,
\]

且最终模型参数数量为：

\[
q=s_1s_2s_3.
\]

修复不得破坏 fixed-size Group-BESS 的支撑数量约束。

### 3.3 必须完成的回归测试

至少包括：

- 固定规模 BCD 的已接受训练损失不应异常增加；
- 返回结果等于已访问且有效候选中的最佳结果；
- 重复支撑状态不会导致无限循环；
- 支撑大小和张量系数形状正确；
- OLS 重新计算的 RSS 与返回值一致；
- 相同输入和随机种子可复现；
- 对极小张量使用穷举支撑作为正确性参照；
- 原有固定规模 Group-BESS 测试全部通过；
- 对 LEMON 的 q80 异常进行修复前后重放。

重点保留旧诊断中的 RSS 轨迹：

```text
2.217202
1.067482
1.366732
1.234092
1.067482
1.366732
1.234092
```

验证修复后不再发生无意义的循环，并确认返回的是合适的最优状态。

### 3.4 修复验收条件

本阶段只判断**算法搜索是否正确**，不要求 LEMON 中 ABESS 的 RMSE 一定改善。

特别注意：

修复 BCD 后，大模型 RSS 可能进一步降低，从而使 MSIC 更偏向大模型。这不意味着修复失败，而是下一阶段需要单独解决的统计选阶问题。

建议将此阶段命名为：

```text
v5.1-bcd-fix
```

保留原 v5 作为对照基线。

## 四、阶段二：研究与诊断 MSIC 自适应选阶（P1）

阶段一通过验收后，再开展 MSIC 研究。

**本阶段先研究和比较候选方案，不立即改变正式算法的默认选阶参数。**

### 4.1 核对当前 MSIC

现有全局精修准则为：

\[
\mathrm{MSIC}_T
=n\log(RSS/n)
+\alpha q\ell_n
+\gamma\ell_n\sum_{m=1}^3
\log {p_m\choose s_m},
\]

其中：

\[
\ell_n=\log\log n
\]

在实际代码中按原有定义做数值保护。

当前设置：

```text
Mode-wise MSIC:
alpha = 1
gamma = 1

Global MSIC:
alpha = 1.5
gamma = 1

one-SE scale = 1.0
q_max = floor(0.7 * n)
```

原 one-SE 规则是启发式容忍带，不是根据交叉验证标准误计算的经典 one-standard-error 方法。

需要检查当前实现是否与上述文档一致。

### 4.2 研究选阶的三个独立因素

**因素一：自由度惩罚强度**

比较不同全局精修 alpha 的效果。

建议初始候选：

```text
alpha = [1.5, 2.0, 3.0]
gamma = 1.0
```

以上只是待检验的预设候选，不是已经确定的新参数。

**因素二：one-SE 风格小模型优先规则**

研究容忍带对最终 q 的影响。

例如对比：

```text
one_se_scale = [0.0, 0.5, 1.0]
```

分别记录最小 MSIC 模型、进入容忍带的候选、最终 q 及验证误差。

不能把增大容忍带直接等同于提高模型泛化能力。

**因素三：选阶准则本身**

除当前 MSIC 外，增加诊断性对照：

- 当前 MSIC；
- 更强自由度惩罚的 MSIC；
- BIC 风格准则；
- 在训练数据内部进行交叉验证的支撑规模选择。

需要明确：固定规模下的候选支撑仍必须在相应训练集内重新搜索，不允许提前在全部数据上选支撑再做交叉验证。

### 4.3 防止 MSIC 从过选变为欠选

历史模拟已经出现：

```text
v2：严重欠选，q≈1
v3：固定真实稀疏度
v4：明显过选，q均值≈112
v5：改善过选与欠选之间的平衡
```

因此不能简单得出“惩罚越强越好”。

新的选阶方案必须同时检查：

- 是否出现 q 接近 1 的欠选；
- 是否经常选择 q 接近容量上限；
- 是否具有稳定的验证误差；
- 是否恢复合理的真实支撑；
- 是否在强信号场景中错误地排除真实变量。

### 4.4 初步实验设计

先使用小规模、具有已知真实支撑的模拟数据，比较不同选阶规则。

至少覆盖：

| 变量 | 研究条件 |
|---|---|
| 样本量 | n=100、200、400 |
| 信噪比 | 低、中、高 |
| 真实支撑 | 原基准矩形支撑 |
| 维度 | 原基准维度，必要时增加高维场景 |
| 数据随机性 | 固定并记录模拟种子，采用相同生成数据比较不同方法 |

真实基准配置可参考原数值模拟报告：

```text
n_train = 200
n_test = 500
dims = (32, 20, 25)
true_sparsity = (4, 3, 5)
SNR = 2
rho = (0.3, 0.3, 0.3)
```

评价：

```text
q_hat
Exact Recovery
Mode-F1
Element-F1
PMSE
R²
Runtime
```

同时记录过选率、欠选率以及 q 达到容量上限附近的频率，并清楚定义这些统计量。

使用相同生成数据及重复种子进行配对比较。

### 4.5 LEMON 只用于诊断，不作为最终调参依据

可以重放已经发现的 q80 异常外折，分析不同 MSIC 规则为何作出不同选择。

但是，不能直接选择让该外折测试 RMSE 最低的参数作为新正式算法参数。

如需以 LEMON 参与选参，应仅在相应训练内部执行；已经反复查看过的正式外层结果属于探索性证据。

## 五、阶段三：版本选择与必要的模拟实验重跑（P2）

### 5.1 采用清晰的版本划分

至少保留三个状态：

| 版本 | 内容 | 用途 |
|---|---|---|
| v5-original | 原始算法，不做修改 | 历史模拟与实证对照 |
| v5.1-bcd-fix | 仅修复固定 BCD，MSIC 不变 | 检验代码修复的影响 |
| v6-msic-candidate | BCD 修复 + 经验证的 MSIC 调整 | 候选新算法 |

不得把 v5.1 和 v6 的修改混在同一个无法分离的版本中。

### 5.2 分两轮进行模拟

**第一轮：算法修复影响评估**

使用相同的数据生成种子、相同模拟配置，比较：

```text
v5-original
v5.1-bcd-fix
```

判断：

- 支撑恢复是否变化；
- q 的分布是否变化；
- PMSE 与 R² 是否变化；
- 是否仍发生大模型过拟合；
- 运行时间是否变化。

这一轮用于确认修复的正确性及其统计影响。

**第二轮：MSIC 调整影响评估**

只在形成有依据的候选方案后，对比：

```text
v5.1-bcd-fix
v6-msic-candidate
```

重点检查是否同时改善过选、欠选和样本外预测，而不只是改善 LEMON 的某一个外折。

### 5.3 正式 full 模拟重跑决策

如果核心 fixed BCD 的修复改变了正式 v5 模拟中使用的模型输出，那么原模拟报告中的 Tensor-ABESS 数值不能直接视为新版本结果。

如果进一步改变 MSIC，原则上需要对最终采用的新算法重新运行完整模拟。

正式重跑应覆盖原终版报告中的：

```text
baseline
correlation
dimension
sample_size
snr
```

并保持原始方法比较框架、样本设计和评价指标。

若 Tensor-GLasso、Vector Lasso 与 Oracle OLS 的代码、输入数据和随机划分均未改变，可复核历史对照产物的配置及指纹后复用；无法严格确认一致时必须重新运行。

原始结果与新结果分别保存，严禁覆盖或合并不同版本产物。

### 5.4 论文和报告版本一致性

如最终采用新算法，应同步更新：

- 核心算法说明；
- 伪代码；
- MSIC 公式和参数；
- 模拟实验配置；
- 模拟实验结果与结论；
- 实证分析所用算法版本；
- 相关图表、表格和运行时间。

不能使用新算法公式，却保留旧算法的模拟数值。
