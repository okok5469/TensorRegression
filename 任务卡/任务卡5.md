# 任务卡5：Tensor-ABESS v5.2 正式发布、项目清理、集群模拟与实证交接

## 一、任务目标

用户现正式批准采用任务卡4推荐的：

**D2 — `v5.2-search-final`**

该版本包含：

1. v5.1 已完成的 fixed BCD 正确性修复。
2. A2 候选规模搜索：旧 caps 范围内完整枚举满足容量约束的整数三元组。
3. 保留原 MSIC（global alpha=1.5、gamma=1、one-SE scale=1）。
4. 保留原 Group-BESS、OLS、初始化逻辑、矩形稀疏结构及公共接口。

**不采用尚未完成独立确认的 MSIC 调整方案。**

本次任务目标：

- 正式发布 v5.2 算法代码。
- 审计并整理混乱的项目目录。
- 安全清理无用的临时文件和重复产物。
- 完整保留以前所有重要算法版本与实验结果。
- 核对集群现有文件，确定最小更新清单。
- 准备 Windows 到 Linux 集群的同步命令或脚本。
- 准备并验证 SLURM 正式模拟脚本。
- 制定完成模拟后的实证重跑方案。
- 生成完整的版本与实验交接文档。

本轮应实际完成本地发布、目录整理、脚本准备及能够执行的验证。

**先不要自动提交 700 个完整集群任务；生成并检查提交脚本，由用户确认后运行。**

## 二、必须遵守的原则

### 2.1 历史结果不得丢失

以下内容必须保留：

- `v5-original` 原始算法源码快照。
- `v5.1-bcd-fix` 算法源码快照。
- 已冻结的 `v5.2-search-final` 候选与发布证据。
- 原始正式数值模拟结果。
- 原数值模拟报告、配置、种子和运行记录。
- 任务卡2、3、4的关键诊断实验及决策证据。
- LEMON、HCP-YA、NKI-Rockland 既有实证数据和结果。
- 团队同步文档及已确认的 Git patch。

历史结果允许统一标注版本，但不允许替换、覆盖或重新命名成新版结果。

### 2.2 清理必须可审计

在删除或移动任何文件前，先生成：

- 当前文件目录与大小清单。
- Git 状态和未提交改动清单。
- 重要文件 SHA256。
- 拟保留文件清单。
- 拟归档文件清单。
- 拟删除文件清单。

**执行顺序：先审计 → dry-run → 安全归档/清理 → 再次检查。**

不得使用：

```bash
git clean -fdx
rm -rf outputs*
rm -rf doc/algorithm_versions
```

等不区分文件内容的破坏性清理命令。

有歧义的文件默认保留，并写入待人工确认清单。

### 2.3 保留研究版本边界

不得将未批准的：

- A1/A3/A4 搜索规则；
- alpha=2/3 MSIC 候选；
- 已废弃的 warm-only BCD 草案；

混入 v5.2 正式算法。

这些研究的必要报告和复现证据仍应保留。

## 四、Phase B：整理项目目录与安全清理

这是本任务的重要工作。

### B1. 先进行项目目录审计

扫描仓库，重点关注：

```text
src/
numerical_simulation/
empirical_analysis/
tests/
doc/
```

分析：

- 哪些是正式算法源码；
- 哪些是测试和实验脚本；
- 哪些是重要模拟结果；
- 哪些是研究过程产生的中间文件；
- 哪些是重复文件；
- 哪些是已经废弃但仍有研究价值的版本；
- 哪些是可以安全再生成的临时缓存。

输出：

```text
doc/PROJECT_DIRECTORY_AUDIT.md
doc/PROJECT_CLEANUP_PLAN.md
```

### B2. 将文件分为三类

**第一类：KEEP — 原位置保留**

必须包括：

- 正式源码与测试；
- 原始 v5、v5.1、v5.2 版本快照；
- 以前的完整数值模拟结果；
- 三个实证项目的既有输入与输出；
- 最终研究报告；
- 版本决策依据；
- 源码指纹、配置和随机种子。

尤其注意：历史结果对应的文件路径可能被报告引用，不要随意移动。

**第二类：ARCHIVE — 归档保留**

适用于：

- 不再使用的研究草案；
- 已停止的实验尝试；
- 重复但具有诊断价值的日志；
- 过时的执行计划；
- 不再使用但可以帮助复现研究过程的源码。

可以集中整理索引，但不得因归档导致已有实验无法复现。

对于大型研究输出，优先保留原位置并通过文档建立索引，而不是复制出第二份巨大的数据集。

**第三类：DELETE — 可安全删除**

仅限经过检查、没有任何必要引用的再生文件，例如：

- `__pycache__`；
- 不需要保留的 `.pyc`；
- 已确定不承担复现或审计作用的临时缓存；
- 经 SHA256 及引用检查确认完全重复且有可靠保留副本的文件。

删除前先运行 dry-run，并保存清理清单。

不得根据文件名包含 `old`、`test`、`temp` 或 `STOPPED` 就直接删除。

### B3. 项目结构建议

尽量沿用已有的结构，不进行大规模重构。

建议让顶层目录职责清晰：

```text
src/
    tensor_abess/          # 正式算法代码

numerical_simulation/      # 数值模拟代码及版本化结果

empirical_analysis/        # LEMON等实证模块

tests/                     # 自动测试

doc/
    releases/              # 正式版本
    algorithm_versions/    # 历史和研究版本快照
    team_sync/             # 团队同步材料
    ...                    # 原有研究报告与记录
```

已有历史研究报告无需全部搬迁。

**本次目标是减少混乱和冗余，不是为了目录美观而改变大量模块导入路径。**

### B4. 清理验收

输出：

```text

```

至少说明：

- 删除了哪些文件；
- 归档了哪些文件；

- 清理前后的磁盘占用；

- Git 状态是否符合预期；

### F2. 实证重跑原则

- 保留各实证的原始受试者集合。
- 保留预测目标及原协变量定义。

### F3. LEMON 的额外要求

- 当前 EEG 特征相对年龄、性别的增量预测价值不明显；

- 是否仍出现 q 接近容量上限；
- 不同外折选阶是否稳定；
- EEG 是否改善仅协变量预测；
- 新版相比旧版的 RMSE、R² 和支撑差异。

不能假定新搜索机制一定提高 LEMON 预测性能。

本任务只准备实证重跑入口与队友操作说明；正式实证在算法发布和对应数据、验证设置确认后再运行。
