# 任务卡10：Tensor-ABESS选阶机制修复与严格训练内CV独立验证

## 一、任务背景

当前已完成任务卡1—9，正式工程版本仍为：

`v5.2-search-final`

本卡的目标不是继续增强BCD支撑搜索，而是研究：

**能否保留v5.2已确认的搜索正确性与结构恢复优势，通过更可靠的选阶机制，减少小样本和弱信号条件下的预测退化？**

- `doc/taskcard9/TASKCARD9_FINAL_DECISION.md`
- `doc/taskcard9/N100_REGRESSION_ATTRIBUTION.md`

以实际源码及冻结实验记录为准，不得仅依据旧算法说明推断当前实现。

### 1.1 已有关键结论

**第一，n=100的预测退化真实存在。**

任务卡9确认：

- v5→v5.1平均PMSE增加1.245466。
- 50组配对中28组恶化。
- 26例q增加，其中25例预测恶化。
- 27例训练RSS下降，但测试PMSE上升。
- 另有同q、同形状、不同支撑导致预测恶化的实例。

因此，退化不仅可能来自选择过大的q，也可能来自相同规模下不同支撑的泛化差异。

**第二，n=400的恢复收益必须重视。**

v5.2的完整整数规模网格使特定n400场景下Exact从1/50升至49/50，同时降低PMSE。

因此，不允许简单通过恢复旧候选网格、压缩所有规模或限制BCD搜索来改善n100的表面指标。

**第三，原MSIC具有已确认的选择局限。**

任务卡9的12例候选重放中，8例存在正的候选池选择差距。

现有证据支持研究更可靠的选择机制，但不支持继续盲目调大MSIC惩罚。

**第四，Warm Start不是本阶段主要修复方向。**

Pure Warm固定规模原型已通过25/25项门禁，但尚无全adaptive泛化收益证据。

本卡不开展Warm性能研究，不将Warm与CV组合。

## 二、研究目标与总体要求

本卡设置三个研究层次。

### P0：核心目标，必须完成

研究严格训练内CV是否能够改善最终模型选择，并与原生MSIC、容量匹配MSIC比较。

核心问题：

1. n100的预测退化能否减轻？
2. 改善究竟来自CV，还是来自内折训练样本减少所造成的容量限制？
3. n400原本良好的恢复表现能否尽量保留？
4. CV能否缓解同形状不同支撑造成的泛化排序问题？
5. 是否会导致强信号欠选或计算成本大幅增加？

### P1：次要目标

诊断选阶之后，最终OLS是否仍有明显有限样本估计风险。

本卡只提出独立的收缩估计研究方案，不直接替换OLS，不与P0混合调参。

### P2：探索目标

研究在预测任务中允许“不使用张量特征”的必要性。

主要面向LEMON等张量增量信号不稳定的实证场景。本卡只做训练信息范围内的可行性研究，不使用已见LEMON外测试结果调参。

# 四、P0：建立三条选阶对照路线

## 任务10.1：实现三臂选阶比较

必须建立三个可以公平比较的研究程序。

### A0：原生MSIC

保持正式v5.2完整流程。

使用当前训练集计算caps、生成候选，并按照正式MSIC和容忍带选择最终模型。

这是正式基线。

### A1：容量匹配MSIC

仍使用原MSIC进行选择，但限制可选模型的容量和候选范围，使其与CV方法具有可比较的候选条件。

其目的是回答：

**如果仅限制候选容量，而不使用CV，预测效果是否也会改善？**

不能将容量限制本身的收益归功于CV。

### A2：容量匹配CV选阶

与A1使用相同的预定义容量规则及可比较候选程序。

但最终选择依据训练内验证误差，而非训练集MSIC。

内折验证必须重新完成：

1. 训练折预处理。
2. 初始化及支撑搜索。
3. 固定候选规模的BCD和OLS。
4. 验证折预测。
5. 候选之间的风险比较。

选定规模或候选程序后，再在完整外训练集上重新拟合，最终预测外测试集。

不能将不同内折中选出的具体支撑误认为同一个固定支撑；跨折比较的对象应是相同的**规模配置或训练程序**。

## 任务10.2：严格解决容量匹配问题

这是本卡最重要的实现细节之一。

对于n100，三折CV的内训练样本大约为66—67，而原模型总参数约束为：

\[
q\leq \lfloor0.7n\rfloor.
\]

因此：

- 完整n100训练时q最多约70。
- 内训练66人时q最多约46。

某些完整训练集合法的规模，在内折不可行。

若直接比较原MSIC和CV，就混合了：

- 模型选择规则变化；
- 训练容量变化；
- 候选规模集合变化。

必须设计可重复的容量匹配协议。

要求：

**第一，预先冻结候选定义。**

用于CV比较的候选规模或候选训练程序，必须在查看其验证误差前确定。

优先构造只依赖样本量、维度和预声明规则的公共容量范围，不得根据验证响应或测试误差动态增加候选。

**第二，保持A1与A2可比。**

二者最终使用的容量约束与候选程序必须一致。

如果原自适应caps依赖训练数据，需明确它在不同内折如何变化。

不得使用包含当前验证响应的信息，为该折构造或优化候选支撑。

如果某个规模无法在全部内折中合法拟合，应按事前冻结的规则排除，或将相应程序判为不可比较；不能根据验证误差决定保留哪些规模。

**第三，保留A0作为原生对照。**

A0不因CV的容量限制而被偷偷修改。

**第四，报告容量本身的影响。**

至少分析：

- A1−A0：容量匹配的影响。
- A2−A1：同容量条件下CV选择的增量影响。
- A2−A0：新方案相对正式算法的总影响。

注意：这些是程序间的配对比较，不得在没有额外随机化或机制实验的情况下，将差值宣称为唯一的因果效应。

若无法构建严格无泄漏、候选生成过程可核验的A1/A2比较，必须先报告技术阻塞，不得用不公平比较得出CV优于MSIC的结论。

# 五、严格CV实现与防泄漏验收

## 任务10.3：训练内CV选择器

建议首先研究3折CV。

对每个预声明候选配置 \(h\)，在第k个内训练折重新拟合：

\[
\widehat B_h^{(-k)}.
\]

验证误差为：

\[
E_k(h)
=
\frac{1}{|V_k|}
\sum_{i\in V_k}
\left(y_i-\widehat y_{i,h}^{(-k)}\right)^2.
\]

汇总时使用按验证样本数加权的误差：

\[
CV(h)=
\frac{\sum_k |V_k|E_k(h)}
{\sum_k |V_k|}.
\]

选择：

\[
\widehat h=\arg\min_h CV(h).
\]

如需并列选择规则，必须提前确定，例如误差数值相同时优先较小q，再按稳定的配置ID排序。

不允许根据外测试误差修改CV选择结果。

如果响应存在协变量调整，则每个内折中的残差化、中心化、标准化都必须只在内训练数据上拟合，再应用于验证折。

特别禁止：

- 完整训练集先选支撑，再做内折验证。
- 用完整训练响应拟合预处理参数后复用至内折。
- 使用外测试集参与CV。
- 根据CV结果事后修改候选规模集合。
- 直接比较不同数据处理尺度下不一致的验证损失。

### 任务10.4：候选程序与缓存一致性

尽量复用正式v5.2固定规模候选搜索的真实执行路径。

在CV中固定一个规模，不意味着可以悄悄替换为另一套初始化或局部优化方式。

必须检查研究适配器是否与正式v5.2候选生成机制一致。

如果不一致，应明确界定：

- 是比较同一候选生成器的不同选阶规则；
- 还是同时改变了候选生成方式。

后者不能称为纯选阶消融。

如技术上无法完全复用，可以提供明确的桥接一致性测试，或者将实验标记为不同程序的整体比较。

缓存键至少区分：

- 数据及划分身份。
- 训练折。
- 候选规模与训练程序。
- 算法源码指纹。
- 预处理配置。
- 随机种子。

不能跨不同训练折错误复用已拟合系数。

要求完成OLS、预测及缓存恢复的一致性验证。

Pilot结束后、正式开发数据生成之前，冻结以下内容：

- 三臂算法定义。
- 公共容量匹配规则。
- CV折数和划分规则。
- 候选程序集合。
- 随机种子管理方式。
- 样本量、信号强度、真支撑形状和相关结构。

- 评价指标和推广门槛。
- 停止规则。
- 独立确认的输入身份与数量。

建议以任务卡9提出的24场景为研究基础：

\[
2(n)\times3(SNR)\times2(\text{真形状})
\times2(\rho)=24.
\]

其中：

- n包括100和400。
- SNR至少覆盖弱、中、强信号。
- 真形状应包含相对容易恢复与具有代表性容量压力的结构。
- 相关结构包含低相关及非零相关条件。

具体参数优先复用现有模拟DGP的已定义取值，不自行创造不同版本的数据生成机制。

需要单独报告真支撑在A0、A1、A2中是否可表示。

例如n100中真形状(4,3,5)可能被原caps排除，这种场景不能简单以Exact为零判断CV失败。

# 八、评价指标与验收门槛

## 任务10.7：同时评价预测、恢复、稳定性和成本

### 8.1 预测表现

必须报告：

- 平均PMSE。
- 中位数PMSE。
- PMSE尾部分位数。
- 三臂配对PMSE差。
- 改善/相同/恶化计数。
- 最坏场景PMSE比。
- n100及弱信号场景单独表现。

尤其要检查：

**CV是否仅改善平均PMSE，却增加部分场景的大幅恶化？**

禁止只报告整体均值。

### 8.2 模型复杂度

记录：

- 最终q及三个模式支撑大小。
- q分布、欠选率、过选率。
- 是否频繁选到容量上限。
- 选择结果在重复数据中的稳定程度。
- 同形状不同支撑情形。

对MSIC与CV选中不同支撑的案例，检查训练RSS与外部PMSE差异，尝试解释CV真正改善了什么。

### 8.3 结构恢复

必须包含：

- Exact。
- REE。
- F1。
- 真形状可表示率。
- 真形状及真支撑进入候选池的比例（在保存的证据支持时）。

特别报告n400。

不能为了改善n100的PMSE而忽略n400原本显著的恢复优势。

对不可表示真形状，明确区分结构性不可达与算法搜索失败。

### 8.4 计算成本

记录：

- 单个训练任务Wall time。
- CPU时间（若可用）。
- 峰值内存。
- 每个CV候选的实际拟合次数。
- 缓存命中与真实计算次数。
- 相对A0的成本倍数。

CV的收益必须结合额外计算代价评价。

### 8.5 推广门槛

在正式开发前，为以下维度设置明确数值门槛：

1. n100预测改善幅度及恶化尾部。
2. 整体配对PMSE。
3. 最坏场景PMSE比。
4. n400 Exact及PMSE的非劣容许范围。
5. 强信号欠选率变化。
6. 最大可接受计算成本。

这些阈值必须记录在冻结协议中，不能根据确认结果更改。

不得仅因CV平均PMSE降低便宣布成功。

如果某些门槛无法在既定样本量下可靠评价，应提前说明统计精度限制，而不是事后将门槛删除。

# 九、P1：最终OLS估计风险的轻量诊断

## 任务10.8：判断是否需要研究支撑内收缩估计

- n100是否频繁选择较大的q。

但本卡不实施正式的Ridge替代实验，也不与CV同时修改选模及估计器。

# 十、P2：允许无张量贡献的预测候选

## 任务10.9：弱信号预测基线设计

当前张量支撑搜索通常要求三个模式支撑均非空。

对于LEMON，已有规范化验证没有显示稳定的EEG增量预测价值。

因此，可以研究在预测层增加：

- 仅协变量模型。
- 协变量＋Tensor-ABESS模型。

两者由严格训练内验证决定是否使用张量特征。

注意：

这不是直接将原矩形支撑结构改成包含q=0的算法，也不是要求在所有模拟中增加截距或协变量。

它首先是**预测流水线层面的可选模型机制**。

本卡只需：

1. 设计训练内选择流程。
2. 明确与协变量残差化、预处理的关系。
3. 说明如何避免信息泄漏。
4. 给出后续独立验证方案。

不得通过已经看过的LEMON外测误差确定切换规则。

这一方向应与P0保持隔离，不纳入本卡正式模拟的三臂比较。

# 十三、最终决策与停止规则

最终报告开头必须回答以下七个问题：

**Q1：n100**

严格训练内CV是否减轻了预测退化？改善幅度及尾部风险如何？

**Q2：容量**

A1相对A0的变化有多大？CV的收益是否主要来自容量缩小？

**Q3：n400**

是否保住完整候选网格带来的恢复优势？若损失Exact，原因是什么？

**Q4：MSIC**

原MSIC究竟在哪些场景选错了模型？CV是否真正改善了最终模型选择？

**Q5：同规模风险**

对于形状相同、支撑不同的候选，CV是否能识别部分训练RSS下降但泛化变差的情况？

**Q6：成本**

CV产生的预测收益是否值得增加的计算量？

**Q7：是否继续修改算法**

根据独立确认结果，提出三选一的明确建议：

- **方案A：** CV通过全部预先冻结的推广门槛。推荐进入候选工程集成阶段，但本卡不直接发布。
- **方案B：** CV改善部分场景，但存在重要恢复、尾部、欠选或成本代价。保留研究实现，不替换正式算法。
- **方案C：** CV未体现可靠收益或未通过关键正确性条件。停止该方向，优先考虑支撑稳定性或估计风险的独立研究。

若独立确认尚未执行或样本量不足，则只能给出暂定研究建议，不得判定为方案A。

请按以下顺序执行：

8. 形成最终报告及下一阶段决策。

可以自主完成已有信息足够支持的工作，不必反复询问用户。

但以下情况必须停止依赖阶段，而不是擅自修补：

- 输入身份核验失败。
- 核心历史正确性断言失败。
- CV存在无法修复的信息泄漏。
- 容量匹配无法形成有效的公平比较。
- 无法取得可信的独立确认数据。
- 计算预算不足。

停止后仍应完整提交已完成的诊断和阻塞记录。

## 本卡最终原则

**保留Tensor-ABESS已经取得的优化正确性和结构恢复收益，将研究重点从“如何找到训练RSS更低的候选”，转移到“如何从候选中选择泛化更可靠的模型”。**

尤其关注n100的明显退化，同时严格保护n400的结构恢复优势。

即使CV最终未能通过推广门槛，也应当通过三臂对照明确容量限制、模型选择与泛化表现各自的作用，为后续算法改进提供可靠依据。
