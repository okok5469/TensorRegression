# 任务卡8：暖启动 BCD 验证与 Tensor-ABESS 自适应选阶改进研究

## 一、研究背景

当前正式算法为 `v5.2-search-final`。

已有研究确认：

1. 修复 fixed BCD 后，训练搜索更充分，但 LEMON 实证预测性能明显恶化。
2. LEMON 中 v5.1 与 v5.2 的15折结果完全一致，说明 A2 网格补全不是此次实证恶化的原因。
3. BCD 修复后，部分大模型训练 RSS 显著下降，原 MSIC 因而更容易选择 q=80。
4. LEMON 实证 RMSE 从原 v5 的0.3717恶化至v5.2的0.5046，而仅协变量基线为0.3175。
5. 当前模型选择机制存在有限样本下控制大模型复杂度不足的证据。

现在另一名队友提供了一版暖启动 BCD，并反馈预测 RMSE、R² 有小幅改善。

但该结果尚未在本项目的相同数据、相同划分及相同评价流程下独立复核。

本任务目标分为两部分：

**研究线A：检验暖启动BCD是否值得采用。**

**研究线B：在保留正确BCD搜索的前提下，研究更稳健的MSIC和模型复杂度控制。**

两条研究线独立进行，最后再综合比较。

本任务不直接修改正式v5.2算法，不发布v6，也不干扰HCP/NKI队友正在进行的v5.2实证。

- 训练拟合与测试泛化的差距；
- q80等异常大模型选择；
- RMSE与R²；
- 支撑选择稳定性。

暖启动不能仅凭训练RSS更低就认定更好。

# Phase D：独立研究MSIC与模型复杂度控制

此阶段与暖启动研究并行。

**核心研究问题：**

> 如何保留fixed BCD充分搜索的能力，同时避免MSIC因大模型训练RSS过低而选择过于复杂的支撑？

## D1. 基线固定

首先使用正式v5.2作为研究基线：

```text
正确性修复后的BCD
A2完整候选规模网格
原caps
原MSIC
```

不要在研究初期将暖启动和MSIC改进混在一起。

必须先得到独立的MSIC变化效果，再研究其与warm BCD的交互。

## D2. 候选选阶方案

建议研究三类策略。

### 方案一：调整MSIC惩罚

保持原公式：

\[
MSIC=n\log(RSS/n)
+\alpha q\ell_n
+\gamma\ell_n\sum_{m=1}^3
\log{p_m\choose s_m}.
\]

以：

```text
alpha=1.5, scale=1
```

作为正式基线。

将历史研究中：

```text
alpha=2, scale=0
```

作为候选对照之一。

可以研究其他预先确定的少量惩罚设置，但必须防止强惩罚导致q=1及严重欠选。

不因LEMON测试结果临时增加候选参数。

### 方案二：训练内部验证选阶

在固定的候选规模搜索机制上，比较MSIC与训练内部验证。

要求：

- 每个内训练折重新执行全部预处理；
- 每个内训练折重新搜索支撑；
- 不使用完整训练集预选的支撑；
- 不使用外层测试误差选q；
- 明确记录不同训练样本量造成的容量限制变化。

这套机制计算成本可能很高，先做预声明的小规模可行性实验。

### 方案三：稳定性或复杂度约束

探索模型复杂度和选择稳定性是否能够辅助MSIC，减少大模型过拟合。

例如：

- 基于训练样本的支撑稳定性评价；
- 复杂模型相对于小模型的额外拟合收益；
- 训练内部预测表现与候选规模的关系。

如果考虑额外正则化或系数收缩，应将其标为独立算法扩展，不再称作单纯MSIC参数调整。

不能通过事后设置`q_max=6`等经验硬限制来优化已经看过的LEMON结果。

## D3. 研究样本设计

划分：

**开发模拟：** 用于比较与筛选候选准则。

**独立确认模拟：** 使用此前未见的随机种子，只有在开发方案冻结后才评价。

应覆盖：

- 小样本和大样本；
- 弱信号和强信号；
- 至少两种真实支撑形状；
- 代表性相关结构；
- 不同候选复杂度。

主要指标：

- PMSE；
- Exact；
- Mode-F1；
- 欠选、过选；
- q接近容量上限的频率；
- 运行时间。

不能只按总体平均PMSE选择新规则，还应检查强信号欠选和小样本过拟合。

## D4. 解释MSIC为何失败

在原v5.2的固定候选库上，分析：

1. 大模型RSS下降多少；
2. MSIC拟合项下降多少；
3. 复杂度惩罚增加多少；
4. 最小MSIC模型与最终one-SE优先模型有什么区别；
5. 哪些场景发生过选；
6. 哪些场景改强惩罚后发生欠选。

必要时增加训练内部验证曲线，帮助理解训练准则与真实泛化误差的偏离。

研究应先形成清楚的数学机制解释，再决定是否值得形成新准则。

1. 不覆盖正式v5.2源码或历史输出。
2. 不根据旧LEMON外层测试集调暖启动参数。
